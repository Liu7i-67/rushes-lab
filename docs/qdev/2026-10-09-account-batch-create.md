## 背景与目标

`scripts/task/账号.csv` 保存待开通人员名单（首行表头，列序：`部门,组别,运营,角色,账号`，共 140 行数据（含表头 141 行），UTF-8 with BOM；`scripts/task/` 整目录被 `scripts/.gitignore` 忽略，csv 是主仓工作区本地文件，不随 git/worktree 走，执行时从主仓取）。需要在 hh2 生产环境 material-storage 中批量创建账号、把服务端生成的临时密码写回 csv、并按「角色」列把用户加入同名用户组。交付一个**可重复执行（幂等）的运维脚本**，生产执行由用户发出指令后运行。

系统现状（调研结论，2026-10-09）：

- 后端 Python FastAPI，prod 入口 `http://192.168.110.221`（服务器本机 `http://127.0.0.1`），dev 入口 `:8090`。
- 认证无 Bearer token，`POST /api/v1/auth/local/login` 后靠 cookie `ms_session`；prod 是 `ENV=production`，`X-User-Id` 通道失效，必须真实管理员登录。
- 建号 `POST /api/v1/admin/directory/users`，入参 `{"username","name"}`，必填仅此两项；`users` 表无 phone 列，手机号即作 `username`（pattern 允许纯数字）。密码由服务端生成，响应字段 `temporary_password` **只回显一次**。重复 username 返回 409。
- 组名→group_id 解析用 `GET /api/v1/admin/directory/groups?q=`（精确匹配 `name`）；建组 `POST /api/v1/admin/directory/groups`（重名 409）；加成员 `POST /api/v1/admin/directory/groups/{gid}/members`（已在组中 409）。组成员关系除 DB 表外还写 OpenFGA tuple，**必须走 API，禁止直写库**。
- 登录限流：同一用户名失败 5 次锁 15 分钟——脚本只登录一次，凭证错误立即退出。

## 功能点明细（逐条可验收）

脚本 `scripts/create_accounts.sh`，bash + curl + awk 实现，**不依赖 jq/python**（目标运行环境 hh2-prod 宿主机）。用法约定：

```
用法: bash create_accounts.sh <csv路径> [--base <API_BASE>] [--dry-run] [--force]
      ADMIN_USER / ADMIN_PASS 环境变量提供管理员凭证（或运行时交互输入，交互输入不回显）
默认: --base http://127.0.0.1（hh2 上 nginx 入口）；dev 测试传 --base http://127.0.0.1:8090
```

1. **CSV 解析**
   - UTF-8 with BOM：读取时剥离 BOM；写回时保留 BOM（Excel 兼容）。
   - 兼容 CRLF 行尾。
   - 首行表头跳过。列序：部门(1) 组别(2) 运营(3) 角色(4) 账号(5)，字段按逗号切分并 trim 空白。
   - **前向填充**：部门、组别两列各自独立地沿列向上找最近非空值填入（跨行继承，含跨空行）。
   - 跳过规则（按序判断）：
     a. 全空行（五列皆空）→ 原样保留，不追加结果列；
     b. 运营为空 → 跳过（状态 `跳过:运营为空`）；
     c. 账号为空 → 跳过（状态 `跳过:账号为空`）；
     d. 角色为空 → 整行跳过（状态 `跳过:角色为空`，决策 D2）。
2. **账号数据**
   - 登录名 `username` = 账号列（手机号）。
   - 姓名 `name` = `部门_组别_运营`（下划线连接填充后的值，原文不做清洗；理论上有空段时按空串拼接，dry-run 核对把关）。
3. **创建账号**：逐行调建号 API。
   - 成功（201）→ `temporary_password` 写入该行第 6 列。
   - 409（登录名已存在）→ 跳过创建，**仍执行加组**（决策 D1），状态 `已存在,补加组`。
   - 其他非 2xx → 状态 `失败:建号 HTTP <code>`，不中断后续行。
4. **加组**：角色值（本表实际取值：`组长`/`运营`/`运营助理`）即组名。
   - 组名→group_id 缓存解析；组不存在 → **自动创建**（决策 D3，409 视为已存在并复用）；建组失败则该行状态追加 `加组失败:建组 <原因>`，不中断。
   - 加成员 409（已在组中）视为成功（幂等）。
   - 加组失败（非 409 的 4xx/5xx）→ 状态追加 `加组失败:...`，不中断。
5. **写回 CSV**：在原 csv 上重写，每行末尾追加第 6 列（账号之后的单元格）；表头行第 6 列写 `临时密码`。
   - 成功行第 6 列 = 临时密码；跳过/失败行 = 状态文本；成功且补组的行 = `临时密码`（密码为主，状态仅失败/跳过时出现；建号成功+加组失败时写 `密码|加组失败:...`）。
   - 全空行保持原样（决策 D6）。保持行序、原有五列内容不变。
   - 写回前备份原文件为 `<csv>.bak`。
6. **幂等/重跑**（决策 D7）：默认第 6 列已非空的行直接跳过（含密码或状态），`--force` 强制重处理全部行。
7. **dry-run**：`--dry-run` 只解析并输出执行计划表（行号/姓名/登录名/角色组/动作），不登录、不调任何写 API、不改 csv。生产执行前必须先 dry-run 人工核对。
8. **登录**：启动时登录一次拿 cookie（curl `-c/-b` cookie jar）；凭证缺失时交互输入（不回显）；登录失败（401/限流 429）打印明确错误并退出，不重试（防触发限流锁定）。
9. **运行摘要**：结束时输出统计（总行/创建/已存在补组/各类跳过/失败计数）与失败行清单。

## 接口定义

不新增接口。消费现有接口（均已有测试覆盖，本任务不改动）：

| 用途 | 请求 | 关键行为 |
| --- | --- | --- |
| 登录 | `POST /api/v1/auth/local/login` `{"username","password"}` | Set-Cookie `ms_session` |
| 建号 | `POST /api/v1/admin/directory/users` `{"username","name"}` | 201 返回 `temporary_password`；409 已存在 |
| 组列表 | `GET /api/v1/admin/directory/groups?q=<组名>` | 精确匹配 `name` 取 `id` |
| 建组 | `POST /api/v1/admin/directory/groups` `{"name"}` | 201；409 已存在 |
| 加成员 | `POST /api/v1/admin/directory/groups/{gid}/members` `{"user_id"}` | 201；409 已在组中 |
