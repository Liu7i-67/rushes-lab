# App 三期打磨第三批(真机 0.1.2+6 遗留四项)· 需求文档

日期:2026-10-22 · 分支:`feat/app-polish-3`(基于 liuqi f4aa320) · 状态:定稿
代码范围:`material-storage/app`(纯前端,无后端改动、无数据库迁移)

## 背景与目标

用户以真机验收 0.1.2+6 后反馈四项仍未解决,本批全部落地:

1. 文件夹「子级 M 项」弱提示仍误导(要求**不再显示**任何子树数字)
2. 九宫格缩略图出现「白屏 → 加载动画 → 显示」三段闪烁,不如早期直接显示
3. 「下拉不友好」优化只覆盖了 5 处,**管理员/用户/用户组/添加成员/建用户所属组/审计操作者**六类场景仍为内联常驻列表形态
4. 新建项目「高级」展开后,输入框浮起标签「MinIO bucket(必填)」只显示下半截

## 决策记录(用户未实时在线,按最合理选项自行拍板)

| # | 模糊点 | 决策 | 理由 |
|---|---|---|---|
| D1 | 文件夹是否保留「子级 M 项」 | **完全删除**。直属>0 → 「N 项」徽标;直属=0 → **不显示任何数字**(含子树>0)。图标实心(子树含文件)语义保留 | 用户原话「不应该展示子级20项」。实心图标已表达「含文件」,数字只会引发「点进去是空的」二次困惑 |
| D2 | 缩略图性能方案 | **加按 assetId 的磁盘位图缓存 + 占位去 spinner + 就位 fade-in**。URL 仅用于首次取字节;二次进入/冷启动/URL 轮换均本地秒出 | 只调占位无法解决重复下载;磁盘缓存是「丝滑」的根因级修复;`path_provider` 已在依赖,无新包 |
| D3 | 缩略图缓存上限与清理 | 150MB,按 mtime LRU,退出登录时整体清空 | 缩略图含用户素材内容,登出必须清(对齐 `thumbnailCache.clear` 既有钩子);150MB 覆盖数千格 |
| D4 | 弹层选择器是否新建组件 | **新建** `remote_picker_sheet.dart`(远程搜索弹层)+ `UserPickerField`;`SubjectPicker`/`GroupMultiSelect` **API 不变**,内部改弹层形态 | 5 处调用点零改动,风险可控;单选走「点选即关」,多选走「勾选 + 底部完成」 |
| D5 | 审计「操作者」空值语义 | 字段右侧提供清除入口(allowClear),清除 = 回「全部操作者」 | 对齐 web AuditPage 的 allowClear 语义;现有 hint「可留空」但无清除路径 |
| D6 | 表单字段高度 | 去掉 `isDense`,显式 `contentPadding: 12/12`,并抽 `AppTextField` 统一;`PickerField` 同步去 isDense | isDense+dense 是裁切直因;统一组件避免后续新增字段再犯 |
| D7 | web 端顺带修复 | **本批不动 web** | 用户诉求明确针对 app 0.1.2+6;web 六场景已达标。仅记录遗留建议(NewProjectModal 两个模板 Select 未开 showSearch、AuditPage UserPicker 单选无 allowClear) |

### 包 B · 缩略图磁盘缓存与平滑加载
- **B1** 新建 `lib/core/thumb_disk_store.dart`(≤140 行):
  - 单例 `ThumbDiskStore.I`;目录 `<getApplicationCacheDirectory()>/thumbs`。
  - `Future<void> init()`:建目录失败静默;启动/写入后触发 LRU 清理至 150MB(按文件 mtime 升序删)。
  - `Future<Uint8List?> read(String assetId)` / `Future<void> write(String assetId, Uint8List bytes)`(临时文件 + rename 原子写)/ `Future<void> clear()`。
  - 文件名 = assetId(仅保留 `[A-Za-z0-9_-]`,其它字符丢弃;空则回退 `sha1` 简写或 `assetId.hashCode`)。
  - **所有 IO 异常一律吞掉并降级**(读返回 null、写静默),widget 测试环境 path_provider 不可用时不得抛。
- **B2** `main.dart`:注册 `session.addSessionClearHook(ThumbDiskStore.I.clear)`;`main()` 内 `ThumbDiskStore.I.init()` 以不阻塞方式发起(unawaited + catch)。
- **B3** `thumbnail_image.dart` 改造(≤170 行):
  - State 持 `Uint8List? _bytes` + `bool _failed`。
  - `_load()`(initState / asset.id 变化时):先 `ThumbDiskStore.I.read(id)` → 命中即 setState;未命中 → `thumbnailCache.urlOf(id)` 签 URL → 用 dio 以 `ResponseType.bytes` GET → `write` 落盘 → setState。忽略已取消(切 id 后旧结果丢弃,沿用 `_tag`/`mounted` 守卫)。
  - `build`:`hasThumbnail == false` → `_fallback`;`_bytes != null` → `Image.memory(_bytes!, fit: cover, gaplessPlayback: true, cacheWidth: <由 LayoutBuilder 宽度 × dpr 取整,clamp 96..600>, frameBuilder: 首次 180ms fadeIn)`;否则 → **纯 `ColoredBox(Tk.fill)`(无 spinner)**。异常 → `_fallback`。
  - 无位图时不再展示 CircularProgressIndicator(用户抱怨的第二段)。
- **B4** 登出清空语义:三处消费点(`asset_tile`/`filmstrip`/`result_row`)零改动,仅 `ThumbnailImage` 内部行为变化。

## 测试功能点

1. **A**:直属 0 + 子树 20 → 行内无「项」字样、无任何数字;直属 5 → 「5 项」;直属 0 + 子树 0 → 无数字;实心图标仍按 subtree>0 点亮。
2. **B**:磁盘有缓存时进入网格不调用 `thumbnail-url`(fake API 记录 0 次),直接渲染 `Image`;无缓存时签 1 次并落盘,第二次进入 0 次;下载失败降级类型色块;`ThumbDiskStore` LRU 超限按 mtime 淘汰;`clear()` 后 read 返回 null;IO 异常不抛。
3. **B**:占位态为 `ColoredBox(Tk.fill)`,不含 `CircularProgressIndicator`(断言 findsNothing)。
4. **C**:`showUserPickerSheet` 多选勾选后「完成(N)」返回 N 项;单选点选即关并返回 1 项;搜索输入经 250ms 防抖只发一次请求;关闭返回 null 表示取消。
5. **C/E**:`UserPickerField` 无值显示 hint、有值显示名称、点按弹出弹层、清除钮回空。
6. **D/E**:`SubjectPicker` 渲染「添加用户 / 用户组」入口,点击弹层选择后 chips 汇总更新;`GroupMultiSelect` 同;5 处调用点(新建项目权限/添加成员/文件夹邀请/文件夹授权/授权模板)不必改签名即可编译并通过既有测试。
7. **E**:`AppTextField` 的 label 不被裁切——断言其 `InputDecoration` 无 `isDense: true` 且 `contentPadding` 垂直 ≥12;新建项目「高级」展开后 `find.text('MinIO bucket(必填)')` 存在且字段渲染无 overflow(`tester.takeException()` 为 null)。
8. **E**:审计筛选栏操作者字段清除后 `onActorChanged` 收到空列表。
9. **回归**:`flutter analyze` 0 issue;既有全量测试全绿(以实际基线为准,当前 766 条)。
