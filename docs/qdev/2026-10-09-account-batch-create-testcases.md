判定口径：
- 状态文本以需求文档原文为准，**半角冒号**：`跳过:运营为空`、`跳过:账号为空`、`跳过:角色为空`、`已存在,补加组`、`失败:建号 HTTP <code>`、`加组失败:...`。

## 8. 疑点与风险记录

1. **行数口径**：需求文档写「共 141 行数据」，实测文件含表头共 141 行（末行有换行符）→ **数据行 140**。F-0 汇总以 140 为准，若 dry-run 摘要报 141 需先核对是否把表头计入。
2. **行级结论随 csv 更新过期（2026-10-09 17:05 用户更新）**：任务单与旧版核对表基于更新前的 csv（如「行 86 全空」、行 47/68/86 跳过运营空、行 50/80 账号空、行 139 角色空、全空 34 行）；更新版（基线 md5 `b33639357a28e4ef404fab04904c1873`）中这些行已变为创建或账号空、全空剩 22 行。跳过判定顺序（全空→运营空→账号空→角色空）本身不变，行级结论一律以 F-0/F-1 基线版为准，执行前先 `md5sum` 核对。
3. **状态文本冒号**：需求文档状态文本为半角冒号（`跳过:运营为空`），自动化 T13-T20 按半角断言；若实现打成全角冒号会红灯，应改实现而非改断言（除非 PM 认可新口径并同步文档）。
4. **`--force` 覆盖密码**：按 D5/D7，重跑时已创建行的第 6 列会被 `已存在,补加组` 覆盖，而 `temporary_password` 只回显一次、覆盖后不可找回。建议实现侧改为「保留原密码，仅在该行为空时写状态」；C-03 先按现状验收并标记 PM 确认点。
5. **dry-run 计划表/摘要格式**：T01-T23 只锚定规范钉死的字符串与计数，不锁排版；T24 为软断言（摘要识别到数值必须一致，识别不到仅 WARN）。当前实现的摘要为 `统计: 数据行=N | 全空行(原样保留)=N | 待创建=N` + `跳过明细: 运营空=N 账号空=N 角色空=N`，T24 可全识别；格式定稿后建议转硬断言。另：被测脚本由后端并行开发、期间有过迭代（摘要行措辞变化），自动化断言已按契约保持对两种措辞兼容；截至本文档落笔，`bash scripts/create_accounts.test.sh` 对当前实现 **26/26 全部通过**（仅供验收参考，以后续运行结果为准）。
6. **行 124（`艺人,,,,`）的组别继承**：列式前向填充会让组别继承上一段「马上有钱组」，姓名理论为 `艺人_马上有钱组_`——但该行运营空先行跳过、姓名不参与 API 调用，无实际影响，核对表已注明。
