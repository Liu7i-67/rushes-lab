# App/Web 第四批(文件夹计数两端统一 + MinIO bucket 收口)· 需求文档

日期:2026-10-22 · 分支:`feat/app-polish-4`(基于 liuqi dab7da7) · 状态:定稿
代码范围:`material-storage/web`(主)+ `material-storage/app` + `material-storage/api`(少量)

## 背景与目标

0.1.3+7 真机验收后用户提出两项:

1. **文件夹图标与数量语义需两端统一**。app 侧上一批已改对,但 **web 端完全不显示数量**;同时明确图标语义边界。
2. **MinIO bucket 字段两端行为不一致**:web 是只有一个选项的下拉,app 允许自由输入——询问是否有风险。

## 目标语义(用户明确定义,两端一致)

以用户给的目录树为例:
```
A                 ← 直属0,子树7(经 B/C)
  B   直属2
  C   直属5
D   直属3
  E                 ← 直属0,子树0
F                    ← 直属0,子树0
  G                  ← 直属0,子树0
```

| 节点 | 子树含文件? | 图标 | 数量 |
|---|---|---|---|
| A | 是(7) | 实心深色(图标2) | **不显示** |
| B | 是(2) | 实心深色(图标2) | 显示 `2 项` |
| C | 是(5) | 实心深色(图标2) | 显示 `5 项` |
| D | 是(3) | 实心深色(图标2) | 显示 `3 项` |
| E | 否 | 空心(图标1) | 不显示 |
| F | 否(子夹 G 也为空) | 空心(图标1) | 不显示 |
| G | 否 | 空心(图标1) | 不显示 |

即两条正交规则:
- **图标**:`subtree_file_count > 0` → 实心深色;否则空心。
- **数字**:`direct_file_count > 0` 才显示,数值 = 直属文件数;`= 0` 一律不显示(即使子树有文件)。

## 调研结论(已实证)

| 项 | 结论 |
|---|---|
| app 图标 | `folder_row.dart:42,76-80`:`hasFiles = subtreeFileCount > 0` → `Icons.folder` + `Tk.fg`(深色实心);否则 `Icons.folder_outlined` + `Tk.accent`。**符合目标** |
| app 数字 | `folder_row.dart:99-105`:`directFileCount > 0` → `Badge('${n} 项', tone: neutral)`;`=0` 不渲染。**符合目标** |
| web 图标 | `FolderTree.tsx:109` `hasFiles = sub.docx`… 实为 `(f.subtree_file_count ?? 0) > 0`;`:152-162` fill 由 hasFiles 决定,**但实心色是 `--ms-ink-muted`(#6B6B68 灰)**,非深色。形状:敏感→`FolderIcon`、有子节点→`FolderOpen`、叶子→`FolderIcon` |
| web 数字 | **完全没有**。`FolderTree.tsx:116-150` 的 title 只有名称/敏感锁/操作菜单 |
| web 类型 | `src/api/types.ts:248-272` 的 `Folder` **缺 `direct_file_count` 字段**(只有 `subtree_file_count`),是 web 无法显示数字的直接原因 |
| 后端 | `FolderOut` 两字段齐全(`models/__init__.py:351`),`list_folders` 双回填(`folders.py:602-610`);`get_folder`/create/update 恒 0(既定契约,web 注释已记) |
| web 复用面 | `FolderTree` 被 5 处使用:主树 PC/移动端 Drawer、批量移动、文件夹移动、百度导入目标夹 → 改一处全生效 |
| bucket:web | `NewProjectModal.tsx:393-399`:antd `Select`,options **前端硬编码**仅 `ms-dev(开发环境)`,默认值与提交兜底均 `ms-dev`;**无桶列表接口**(后端不存在 `/buckets`) |
| bucket:app | `new_project_form.dart:117-127`:自由 `TextFormField`,默认 `ms-dev`,`maxLength: 63`,校验仅「非空 + ≤63」 |

| bucket:收口 | `projects.py:107-111`:非系统 admin 提交的 bucket **被强制改为 `ms-dev`**;仅系统 admin/org admin 的输入原样落库 |

## 决策记录(用户未在线,按最合理选项拍板)

| # | 模糊点 | 决策 | 理由 |
|---|---|---|---|
| D1 | web 数量文案格式 | 与 app 对齐用 **`N 项`**(小号 pill,底色/字色走 tokens) | 两端同一文案避免认知差;用户例子写「显示2」是示意数量而非文案规范 |
| D2 | web 实心态颜色 | 由 `--ms-ink-muted`(灰)**改为 `--ms-ink`(深色)**,与 app `Tk.fg` 对齐 | 用户明确「深色文件夹图片」;muted 灰不足「深色」 |
| D3 | web 图标形状是否统一 | **保留现有形状规则**(敏感/有子节点 → `FolderOpen`、叶子 → `Folder`),只改填充色 | 用户诉求是「实心/空心 + 数量」;形状属既有信息层级(打开态提示),改它属额外视觉变更、无需求依据 |
| D4 | 是否同步 app 的移动/批量移动/百度目标夹选择器 | **不涉及**。它们恒空心、无数字,数据源虽同为 folders.list 但语义是「选目标」而非「浏览内容」 | 用户只定义文件夹列表展示;贸然加数字反而干扰选择操作 |
| D5 | app bucket 改法 | **改为与 web 同款的单选项下拉**(复用 I2 既有 `PickerField` + `showPickerSheet`),选项常量集中一处定义 | 彻底消除自由输入;与 web 完全一致;不新增依赖 |
| D6 | 两端的桶选项来源 | 两端各自硬编码同一份列表(`ms-dev(开发环境)`),并在文档/注释标明「新增桶须两端同步改」 | 后端无桶列表接口(建一个属超范围);PoC 单桶部署事实 |
| D7 | 后端是否加 bucket 格式校验 | **加**:`min_length=3` + S3 命名 pattern,纵深防御 API 直调 | 前端下拉已堵住 UI 路径,但 admin 走 API 仍可传任意串;成本一行约束;存量值 `ms-dev`/`ms-dev` 均合法,零迁移 |
| D8 | 是否校验桶「存在性」 | **不做**。后端创建路径不连 MinIO,做存在性校验要引入 S3 调用与新失败模式 | 超出本批;前端下拉单选项已把实际可达值收敛为 `ms-dev`。记入遗留:将来多桶部署应改为后端返回可用桶列表 |
| D9 | 非 admin 的 bucket 自由度 | **不变**(仍强制 `ms-dev`) | 既有提权收口,与本批无关,勿动 |

## 功能点明细

### 包 W · web 端(主)
- **W1** `src/api/types.ts`:`Folder` 接口补 `direct_file_count?: number`,注释按后端契约写(仅 `GET /folders` 列表回填,create/get 恒 0,消费侧 `?? 0` 回落)。
- **W2** `src/components/FolderTree.tsx` title 区:名称之后、敏感锁之前/之后(择一,不与 ops 挤)渲染数量 pill —— 仅当 `(f.direct_file_count ?? 0) > 0`:
  - 文案 `${n} 项`
  - 小号(11px)、`flexShrink: 0`、不参与 elide(名称 span 已有 ellipsis + flex:1)
  - 视觉为轻量 pill:背景取现有 surface 次级色、字色 `--ms-ink-muted`,圆角胶囊;不得抢名称视觉层级
- **W3** `src/components/FolderTree.tsx` 图标:实心态颜色 `--ms-ink-muted` → `--ms-ink`(敏感夹维持 `--ms-sensitive` 不变);空心态维持 `--ms-ink-muted`。形状逻辑不动(D3)。
- **W4** 注释同步:把「D1 定档:仅图标区分,无数字、无 tooltip」改为新语义(图标=子树含文件;数字=直属且>0 才显示)。

### 包 A · app 端
- **A1** 新建 `lib/features/projects/minio_buckets.dart`:导出 `kMinioBuckets`(小数据类/记录,含 `value` 与中文 `label`,当前一项 `ms-dev` → `ms-dev(开发环境)`),文件头注明「web `NewProjectModal` 硬编码同源,新增桶须两端同步」。
- **A2** `new_project_form.dart`:bucket 字段由 `AppTextField` 改为 `PickerField`(label `MinIO bucket(必填)`,value=当前选中 label,hint 缺省),`onTap` 弹 `showPickerSheet<String>`(items = bucket values、initial、labelOf 映射、searchable: false——单选项搜索无意义)。
- **A3** `new_project_sheet.dart`:`_bucket` 由 `TextEditingController(text:'ms-dev')` 改为 `String _bucket = kMinioBuckets.first.value`;`dispose` 移除该 controller;`_hasUnsavedInput` 按字符串比较;`_submit` 直接传 `_bucket`;`_crossValidate` 不受影响(bucket 原由 Form validator 校验,改为下拉后恒有值 → 移除 bucket 的 validator 分支与新项目表单里的 maxLength/长度校验)。
- **A4** `new_project_form.dart` 的 props 增加 `bucket` / `onBucketChanged`(或复用现有数据类扩展),删除 bucket controller 透传。
- **A5** 既有测试适配:`test/features/new_project_sheet_test.dart` 中依赖 `find.widgetWithText(TextField,'MinIO bucket(必填)')`、输入 bucket 文本、`maxLength` 计数器等断言改为「点按字段 → 弹层出现 `ms-dev(开发环境)` → 选中」路径;保留「高级」展开断言。

### 包 B · 后端(纵深防御)
- **B1** `api/app/models/__init__.py`:`ProjectCreateIn.minio_bucket` 由 `Field(..., max_length=63)` 改为 `Field(..., min_length=3, max_length=63, pattern=r"^[a-z0-9][a-z0-9\-]*[a-z0-9]$")`。注释写明:S3 桶名口径(小写字母/数字/连字符,3-63,首尾非连字符);前端两端已改下拉,此为 API 直调兜底。
- **B2** 新增纯模型单测 `api/tests/test_project_create_in_bucket.py`(不依赖 DB):合法 `ms-dev`/`abc`/`a1-b2` 通过;非法 `MS-DEV`(大写)、`ms_dev`(下划线)、`ab`(过短)、`-abc`/`abc-`(首尾连字符)、64 字符超长 → `ValidationError`。
