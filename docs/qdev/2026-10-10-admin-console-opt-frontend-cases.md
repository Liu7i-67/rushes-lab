# 管理后台优化六项 — 前端手工用例清单(T18-T25)

> **供专职测试阶段执行**(本文件只列用例,不含执行结果)。
> 需求依据:`docs/qdev/2026-10-10-admin-console-opt.md`(功能点 F1-F7、前端改动点 W1-W13、测试功能点 T18-T25)。
> 环境约定:内网**纯 HTTP**部署(F1 复制降级的前提)、antd v6、`--ms-*` token 主题。
> 角色约定:
> - **sysadmin** = 系统管理员(Evan,org admin);
> - **deleter** = 所在用户组已开「可删除项目」(can_delete_project)的普通成员;
> - **plain** = 无任何特殊权限的普通用户。
>
> 每条用例标注:对应需求功能点(F*)/ 前端改动点(W*)。执行顺序建议 T18 → T19-T24 → T25(回归收尾)。

## T18 构建与静态检查(全自动)

- **对应**:全局(W13 已预装 copy-to-clipboard 依赖);验收标准即 F1-F6 前端交付门槛。
- **前置**:web/ 目录依赖已安装(pnpm install)。
- **步骤**:
  1. `pnpm build`(含 tsc 类型检查);
  2. `pnpm lint`。
- **预期**:两条命令均 0 退出;无 TS 类型错误;无 lint error(warning 需记录)。

## T19 纯 HTTP 环境 7 个复制点全部成功(F1 / W1-W6)

- **对应**:F1.1-F1.3(统一工具 `web/src/utils/copy.ts` copyToClipboard);重点回归「HTTP 非安全上下文 navigator.clipboard 不可用」场景。
- **前置**:系统以 **http://内网IP:port** 访问(非 localhost,确保非安全上下文);浏览器为常规现代浏览器(复制应成功);另备一台极旧浏览器(如 Chrome < 66,验证失败降级提示,可选项)。
- **步骤与预期**(逐点验证:点击复制入口 → 粘贴到任意文本框比对内容):
  | # | 复制点 | 入口 | 预期 |
  |---|---|---|---|
  | 1 | 新建用户**临时密码** | 用户管理 → 新建用户提交后的 TempPasswordModal | toast「已复制」,粘贴值=临时密码(W8) |
  | 2 | **分享链接** | 资产 → 分享(ShareModal)创建链接后 | toast + 粘贴值=分享 URL(W2;原手写 execCommand 降级已删除) |
  | 3 | **Asset ID** | 资产详情/列表的复制 ID 入口 | 粘贴值=资产 UUID(W6) |
  | 4 | **minio_key** | 资产详情的对象 key 复制入口 | 粘贴值=minio key(W6) |
  | 5 | **open_id** | 用户/成员相关的 open_id 复制入口 | 粘贴值=open_id(W4/UserMenu 或对应组件) |
  | 6 | **百度授权链接** | 百度网盘绑定弹窗(BaiduBindModal) | 粘贴值=授权 URL(W5) |
  | 7 | **申请链接** | 申请链接创建弹窗(RequestLinkCreateModal) | 粘贴值=申请 URL(W3) |
- **降级验证(可选)**:极旧浏览器上任一复制失败时,出现「手动复制」提示文案(含可手动选中的文本),不静默失败;AssetSummaryPanel 原无兜底的两处(W6)失败时必须有提示。

## T20 组成员弹窗:限高滚动 + 组内搜索 + 计数(F2 / W7)

- **对应**:F2.1-F2.3。
- **前置**:sysadmin;准备一个 **100+ 人**的用户组(可先用建用户接口/脚本造 100+ 用户,97 人含关键字见下);打开 管理后台 → 用户组。
- **步骤**:
  1. 点击该组「成员」打开 GroupMembersDrawer;
  2. 观察弹窗高度与滚动;记录标题计数;
  3. 在成员搜索框输入某成员**用户名**的中间子串(不区分大小写,如 `ABC` 匹配 `xabc99`);
  4. 分别再用**姓名**子串、**邮箱**子串各搜一次;
  5. 输入一个不存在的子串;再清空搜索(allowClear ×)。
- **预期**:
  1. 成员列表容器限高 `min(420px, 60vh)` 且可滚动,弹窗整体不被成员数撑开、页面无溢出;
  2. 未过滤时标题为「成员—{组名}(N 人)」;
  3-4. 三种子串均命中(用户名/姓名/邮箱,忽略大小写),仅显示匹配成员;过滤时标题变为「成员—{组名}({匹配数}/{总数} 人)」;
  5. 无匹配时列表为空、计数「0/{总数}」;清空后恢复全量与「N 人」标题。
  - 专项断言(对应 T20 口径):造 100 人组、其中 3 人名字含「测试」,搜「测试」→ 计数 **3/97** 之外成员不显示;清空恢复 97。

## T21 新建用户支持指定用户组(F3 / W8)

- **对应**:F3.1-F3.4(后端 §1)。
- **前置**:sysadmin;存在 ≥2 个用户组(记为组 A、组 B)。
- **步骤**:
  1. 用户管理 → 新建用户:**不选组**直接提交(填用户名/姓名);
  2. 再新建一个用户:在「用户组(可选)」多选中搜索并选 **组A + 组B**,提交;
  3. 观察临时密码弹窗;关闭后分别在 组A、组B 的成员弹窗中搜索新用户;
  4. 多选框中搜索一个不存在的组名。
- **预期**:
  1. 不选组可正常提交,201 成功,临时密码正常回显;
  2. 选 2 组提交成功,临时密码弹窗仍正常(一次回显、可复制,见 T19.1);
  3. 两个组的成员列表都直接包含该新用户(无需二次加人);
  4. 搜不到时无崩溃、无误选;刷新页面后用户列表出现新用户。

## T22 编辑用户(F4 / W8)

- **对应**:F4.1-F4.4(D3 全量同步、D6 email null、D7 username 不可改)。
- **前置**:sysadmin;存在用户 U(属于组A,有姓名/邮箱)。
- **步骤**:
  1. 用户行点「编辑」打开 EditUserModal,核对回显;
  2. 修改姓名 + 邮箱,保存;
  3. 再次编辑:把组从 [组A] 改为 [组B](勾选集为准),保存;
  4. 第三次编辑:清空邮箱(显式清空语义),保存;
  5. 观察 username 输入框;保存后看列表是否即时刷新;
  6. 审计页核对 user_updated 与 group_member_added/removed 事件。
- **预期**:
  1. username 只读回显(注明提交后不可改),name/email/当前组正确回显;
  2. 保存成功,列表立即显示新姓名/邮箱(无需手动刷新);
  3. 保存后组A 不含 U、组B 含 U(全量同步,移出+加入双写);
  4. 邮箱被清空,列表显示为空;
  5. 列表行即时更新(react-query invalidate);
  6. 审计含 user_updated(changes 带 old/new、groups_added/removed)及对应成员事件。

## T23 用户列表分页 + 总数(F5 / W8)

- **对应**:F5.1-F5.3(D4/D5)。
- **前置**:sysadmin;用户数 > 20(不足则先造一批,如 25 个)。
- **步骤**:
  1. 打开用户管理页,看列表头部与底部;
  2. 点第 2 页、第 3 页;调整 pageSize(若开放);
  3. 输入 q 搜索某关键字、切换 is_active 筛选;
  4. 清除筛选回到全量。
- **预期**:
  1. 头部显示「共 {total} 名用户」;底部 antd Pagination 默认 pageSize 20,showTotal 显示总数;
  2. 翻页数据正确不重叠(limit/offset 响应结构 {items,total,limit,offset});
  3. **筛选(q/is_active)变化后自动回到第 1 页**,total 变为过滤后数量;
  4. 清除后 total 恢复;`GET /api/v1/users`(Picker 数据源)不受影响(F5.3)。

## T24 项目逻辑删除 + 恢复 + 组开关(F6 / W7/W9/W10)

- **对应**:F6.2-F6.8(接口 §5-§9)。
- **前置**:sysadmin;准备:组 G(普通组)与成员 D(deleter 候选)、普通用户 P(某项目 project admin 但无 deleter 权限)、测试项目 X、Y。
- **步骤与预期**:
  1. **组开关与显隐**:组管理 → 编辑组 G → 打开「可删除项目」开关保存 → 组行展示该 flag(与 can_create_project 同样式);再次编辑可关闭;
  2. **入口显隐**:D 打开项目页 → 项目卡片操作区出现「删除项目」;进入项目 X 详情页 → 头部出现「删除项目」;plain 用户与(未开 flag 的)项目 admin P **看不到**删除入口;
  3. **删除交互**:D 点击「删除项目」→ Popconfirm 二次确认,文案说明「深隐藏+可恢复」;确认后项目从列表消失;直链访问 X 详情 → 404;sysadmin 的列表/直链同样不见;
  4. **已删除项目页**:D(sysadmin 亦可)点项目页头部「已删除项目」→ Modal 分页列表(共 N 条、翻页)含 X,显示删除人姓名与时间;plain 用户无此入口且接口 403;
  5. **搜索**:在已删除列表按 X 的 code/名称关键字过滤,命中;
  6. **恢复**:点 X 行「恢复」→ Modal 列表移除 X,主列表重新出现 X,详情可打开;
  7. **边界**:对同一项目重复删除(接口层)→ 404;未删除项目在已删除列表搜不到;恢复后再次「恢复」→ 404(接口语义,前端不提供入口);
  8. **审计**:审计页可查 project_deleted / project_restored、group_updated(带 can_delete_project 变更)事件。
- **回归点**:删除/恢复后,项目成员、资产、分享链接在恢复后均完好(D10 不动数据)。

## T25 回归:原功能不受影响(全局)

- **对应**:F1-F6 改动的回归面(需求 T25)。
- **前置**:同 T19-T24 环境;覆盖以下既有功能各一轮主路径。
- **步骤与预期**(逐项通过即勾选):
  1. **登录**:本地账号密码登录、首登强制改密、登出;禁用用户立即 401;
  2. **项目列表**:公开/私有项目可见性符合权限;项目创建(组 creator 开关路径)正常;
  3. **项目成员管理**:加/移用户与组成员、角色变更即时生效;
  4. **上传下载**:普通上传、大文件、下载链接、缩略图/预览正常;
  5. **审计查询**:审计列表过滤(event_type/actor/时间)与导出正常;
  6. **权限模板**:grant-templates 列表/应用正常(写端点仍限 sysadmin);
  7. **组 CRUD**:建组/改名/删组、加移成员、组成员弹窗(T20 之外的基础交互)正常;
  8. **用户组 picker 数据源**(GET /api/v1/users、/groups)不受用户分页改造影响(F5.3)。
- **通过标准**:以上全部无阻断缺陷;发现的视觉/交互瑕疵单独记录不阻断。
